# Система складского учета и фулфилмента (WMS)

## 1. Цель проекта

Разработать WMS-платформу с клиентским кабинетом для:
- прозрачного контроля складских операций для селлера (заказчика);
- оперативного выполнения процессов исполнителем (складом);
- централизованного администрирования пользователей, справочников и доступов.

Система охватывает полный цикл обработки товара:
**прибытие → приемка → брак/расхождения → комплектация по коробам → закрытие коробов → отгрузка → остатки/резервы → отчеты/архив**.

---

## 2. Роли и права доступа

### 2.1 Исполнитель (склад)
**Права:** создание/редактирование всех операционных данных.

**Доступные действия:**
- приемка через сканер и вручную;
- фиксация брака и фото;
- комплектация коробов;
- закрытие коробов и печать этикеток;
- оформление отгрузок;
- корректировки и комментарии;
- работа с мобильным интерфейсом/ТСД.

### 2.2 Заказчик (селлер)
**Права:** только просмотр и выгрузка отчетов.

**Доступные действия:**
- отслеживание статусов поставок и отгрузок;
- просмотр фото, брака, расхождений, остатков;
- просмотр новостей;
- выгрузка Excel-отчетов.

### 2.3 Администратор
**Права:** полный доступ + системное управление.

**Доступные действия:**
- управление пользователями, ролями, заказчиками;
- управление справочниками (в т.ч. причины брака);
- аудит логов;
- публикация новостей/уведомлений;
- системные настройки.

---

## 3. Бизнес-процессы

1. Прибытие (забор) груза.
2. Приемка товара (сканер/ручной ввод).
3. Фиксация брака.
4. Автоматический журнал расхождений.
5. Комплектация по коробам.
6. Закрытие короба с генерацией QR/штрихкода.
7. Отгрузка (короба/паллеты).
8. Учет остатков и резервов в реальном времени.
9. Формирование отчетов (Excel).
10. Архивирование завершенных поставок.
11. Уведомления и новости для селлеров.

---

## 4. Функциональные требования по модулям

### 4.1 Прибытие груза
- Фиксация даты/времени прибытия.
- Указание машины и водителя.
- Прикрепление документов (накладные, акты).
- Загрузка фото.
- Смена статусов: `ожидается` → `прибыл` → `принят`.
- Видимость всей информации для заказчика.

### 4.2 Приемка товара
**Режимы:**
1) Сканер (HID/ТСД): чтение штрихкода, автопоиск SKU, инкремент количества.  
2) Ручной: выбор товара + ввод количества.

**Поля позиции:**
- наименование;
- SKU/артикул;
- штрихкод;
- размер;
- цвет;
- партия;
- срок годности;
- количество.

Система фиксирует отклонения между ожидаемым и фактическим количеством.

### 4.3 Брак
- Регистрация бракованных единиц.
- Выбор причины брака из справочника (+ комментарий).
- Фиксация количества и фото.
- Привязка к товару, партии и поставке.

### 4.4 Журнал расхождений
Автоматическое создание записи при любом несоответствии:
- ожидаемое количество;
- фактическое количество;
- разница;
- причина;
- комментарий;
- дата/время;
- ответственный.

### 4.5 Комплектация по коробам
- Создание коробов с уникальным номером.
- Добавление товаров сканером или вручную.
- Отображение состава короба в реальном времени.
- Привязка пункта назначения (СЦ/город).

### 4.6 Закрытие короба
При закрытии:
- фиксируется неизменяемый состав;
- генерируется QR/штрихкод;
- формируется этикетка;
- товар немедленно списывается с доступного остатка;
- статус короба меняется на `закрыта`.

### 4.7 Этикетки
Этикетка содержит:
- номер короба;
- пункт назначения;
- дату;
- QR/штрихкод.

Поддержка генерации и печати.

### 4.8 Отгрузка
- Создание отгрузки.
- Выбор коробов к отгрузке.
- Указание количества паллет и коробов.
- Прикрепление фото.
- Статусы: `собирается` → `готово к отгрузке` → `отгружено`.

### 4.9 Остатки
Карточка остатка:
- товар;
- SKU/артикул;
- штрихкод;
- партия;
- срок годности;
- количество;
- брак;
- доступно;
- в резерве.

Фильтры: по товару, партии, сроку годности.

### 4.10 Резервирование
- Резерв под заказ.
- Уменьшение доступного остатка.
- Отдельный учет зарезервированного количества.

### 4.11 Отчеты и Excel
Выгрузки в Excel по сущностям:
- остатки;
- приемка;
- брак;
- коробки;
- отгрузки;
- журнал движений.

### 4.12 Архив поставок
- Автоматический перенос завершенных поставок в архив.
- Доступ к истории и фильтрам архива.

### 4.13 Комментарии
Комментарии с историей изменений для:
- поставок;
- товаров;
- брака;
- коробов;
- отгрузок.

### 4.14 Уведомления
События уведомлений:
- прибытие груза;
- завершение приемки;
- фиксация брака;
- закрытие короба;
- отгрузка;
- публикация новости.

Этап 1: in-app уведомления.  
Этап 2: email / push / Telegram.

### 4.15 Новости для селлеров
Поля новости:
- заголовок;
- текст;
- дата;
- автор;
- статус (`черновик`, `опубликована`, `архив`);
- вложения.

Функции:
- создание/редактирование/архивация;
- публикация для всех селлеров;
- отметка новых новостей;
- просмотр деталей и вложений;
- уведомление при публикации.

## 5. Работа со сканерами

Поддерживаемые устройства:
- USB/Bluetooth-сканеры в режиме HID (как клавиатура);
- мобильные ТСД на Android.

Требования:
- быстрый ввод без перезагрузки страницы;
- устойчивость к повторному скану;
- валидация неизвестных штрихкодов.

---

## 6. Журнал движения товара

Для каждой операции создается проводка движения:
- приемка (+);
- брак (перевод в дефектный сток);
- корректировка (+/-);
- упаковка (доступный сток → в короб);
- отгрузка (в коробе → отгружено);
- резервирование (доступный → резерв).

Обновление остатков — мгновенное, транзакционное.

---

## 7. Логирование и аудит

Система сохраняет:
- пользователя;
- тип действия;
- дату/время;
- старое и новое значение полей;
- сущность и идентификатор записи.

Логи доступны администратору и не редактируются пользователями.

## 11. Критерии приемки MVP

MVP считается готовым, если:
1. Исполнитель может выполнить полный цикл от приемки до отгрузки.
2. Заказчик видит статусы, фото, остатки и отчеты в личном кабинете.
3. Остатки, резервы и движения обновляются в реальном времени.
4. Есть выгрузка ключевых отчетов в Excel.
5. Реализованы аудит-логи и базовые уведомления в системе.

## 12. Что реализовано в коде (текущий MVP backend)

В репозитории добавлен базовый backend API на FastAPI + SQLite, покрывающий ключевые процессы:
- товары (`/products`);
- поставки и статусы (`/supplies`, `/supplies/{id}/status`);
- приемка с автоматическим движением остатков (`/receptions`);
- фиксация брака (`/defects`);
- резервирование (`/reservations`);
- короба: создание, добавление товаров, закрытие (`/boxes`, `/boxes/{id}/items`, `/boxes/{id}/close`);
- отгрузки и статусы (`/shipments`, `/shipments/{id}/status`);
- новости и публикация (`/news`, `/news/{id}/status`);
- остатки и журнал движений (`/stocks`, `/movements`);
- служебная проверка (`/health`).

### Быстрый запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

### Тесты

```bash
pytest
```

## 13. Следующий этап (реализовано в продолжении)

Добавлены улучшения поверх MVP:
- базовый RBAC через заголовки `x-user-role` и `x-user-name` (`admin`, `operator`, `customer`);
- аудит-действий в таблицу `audit_logs`;
- автоматический журнал расхождений `discrepancy_log` при несовпадении expected/actual на приемке;
- валидация допустимых статусов поставок, отгрузок и новостей;
- эндпоинты просмотра `/notifications`, `/discrepancies`, `/audit-logs`.

### Проверка ролей

Примеры:
- `customer` может читать (`GET /stocks`, `GET /products`), но не может создавать товары (`POST /products` → 403);
- `admin` получает доступ к `GET /audit-logs`;
- `operator` выполняет складские операции.
